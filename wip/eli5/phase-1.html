フェーズ 1（調査）の説明

main.sh に --verbose を足す前に、今の main.sh が何をしているかを確かめた作業です。コードは変えていません。

いちばん大事なこと

main.sh は「入力ファイル・絞り込みの言葉・出力ファイル」の 3 つを受け取り、入力から言葉を含む行を探して番号を振り、<出力の接頭辞>.txt に書くスクリプトです。今回の調査では、この動きを読んで、実際に確かめた項目を整理しました。

分かったこと

  • 引数が 3 つに足りないと、使い方を表示して終了コード 1 で止まる。
  • 入力ファイルが無い（またはフォルダ）と、エラーを表示して終了コード 1 で止まる。
  • 絞り込みは「含むかどうか」だけで、正規表現ではない。a.b は a.b の行だけに当たる。
  • 一致が無いと、空の出力ファイルができて終了コード 0。
  • 出力先のフォルダが無いと、終了コード 2 になる（README の書き方とは違う）。
  • 今の --verbose は、位置の引数として扱われ、「入力ファイルが見つかりません」で止まる。

足すときに触る場所

大きく 3 か所です。

  1. 引数の受け取り（最初の方）。--verbose を先に見つけて外してから、数を数える。
  2. 経過を出す場所（入力の確認の後と、絞り込みの前後）。出すのは標準エラーだけにする。
  3. 使い方の文面（1 行か 2 行）。

まだ確かめていないこと

  • 調査の多くは、サブエージェントの報告を基にしている。メインが打ち直して確かめたものではない。
  • README にある「テスト」の行と、コメントの意味は分からないまま。
  • テストのファイルは今のリポジトリには無い。流せるテストは無い。
