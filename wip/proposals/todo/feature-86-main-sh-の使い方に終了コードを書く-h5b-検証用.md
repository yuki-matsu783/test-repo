## 目的

`main.sh` の引数が足りないときに出す使い方メッセージに、終了コード 1 で終わることを書く。

## 範囲

- `main.sh` の引数チェック（`if [ "$#" -lt 3 ]`）の中の `echo` の文言だけ。
  - 変更前: `使い方: sh main.sh <入力ファイル> <絞り込みパターン> <出力の接頭辞>`
  - 変更後: `使い方（終了コード 1）: sh main.sh <入力ファイル> <絞り込みパターン> <出力の接頭辞>`
- 終了コード（`exit 1`）と、ほかの処理は変えない。

## 対象外

- 入力ファイルが無いときのエラー文言、正常時の出力（`<出力の接頭辞>.txt`）の形式。
- `docs-9001-exitcode` ブランチと、その手で切ったコミット `0586d13`。このチケットでは触らず、cherry-pick もしない（履歴の書き換えを避け、作業は新しいワークツリーの中で改めて書く）。
- README など、使い方を書いた他の文書の更新（本文に使い方が無いことを確かめたうえで、必要ならあとで別に扱う）。

## 完了の確かめ方

- `sh main.sh` を引数なしで実行したとき、標準エラーに `使い方（終了コード 1）:` を含む行が出て、終了コードが 1 である。
- `sh main.sh <存在する入力> <パターン> <接頭辞>` が従来どおり `<接頭辞>.txt` を作り、終了コードが 0 である（回帰の確認）。
- 差分が `main.sh` の 1 行だけであること（`git diff --stat` で確かめる）。

## 計画の理由

作業は 1 ファイル・1 行で、フェーズを分ける理由が無い。`quick-work`（前のステップが次に先行する一直線の 1 フェーズ）で足りる。レビューは MR で行う（`review: mr`）。
