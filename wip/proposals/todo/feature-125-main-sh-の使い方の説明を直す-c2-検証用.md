## 目的

main.sh のヘッダーの「使い方」の説明に、実装が実際にすることで書かれていないものを足す。読んだ人が、既存の出力ファイルを失うことや、空の結果を誤って成功と読むことを防ぐ。

読み合わせで分かったこと:

- 使い方の行、引数の 3 つ、入力が無いときのエラー、終了コード 1、例（`errors.txt` ができる）は、実装と合っている
- 書かれていない動作が 2 つある
  1. 出力先の `<出力の接頭辞>.txt` が既にあると、確認なしで上書きされる（`awk ... > "$output"` で書き直すため）
  2. 絞り込みパターンに一致する行が 0 件でも、空の `<出力の接頭辞>.txt` ができ、終了コードは 0 になる（awk が何も出力しないため）

どちらも実装を読んで確かめた。この作業のセッションでは、一時ファイルを使った実行による確認はできなかった（ワークスペースの書き込み制限で止まった）。実行による確認は完了の確かめ方の中でやる。

## 範囲

- `main.sh` のヘッダーコメント（使い方・引数・出力・終了コード・例の説明）。上の 2 つの動作を、同じ書き方で 1 行ずつ足す
- 必要なら、説明の中の文言を実装に合わせて直す（例: 「番号を振って」の出力形式が分かるように、出力の 1 行の形を例に書く）

## 対象外

- `main()` の中のロジック、引数の検査、エラーメッセージの文言、awk の処理、出力の形式そのもの
- 出力の上書きを防ぐ・一致 0 件を失敗にする、といった挙動の変更。それは説明ではなく判定の変更で、ユーザに相談する
- `README.md`、`index.html` など main.sh 以外のファイル

## 完了の確かめ方

- `sh -n main.sh` が終了コード 0 で通る
- ヘッダーに、出力の上書き、一致 0 件のときも空のファイルができて終了コードが 0 になること、が書かれている
- 実装を読み直し、書いた説明と実際の動作が 1 対 1 で合う（引数の順、出力のファイル名、終了コード）
- 一時ディレクトリで実行して確かめる（`ccnavi` のワークスペース制限に当たる場合は、その旨を報告に書く）:
  - 一致あり: `sh main.sh access.log ERROR errors` が `errors.txt` を書き、中身は `番号. 行` の形
  - 一致 0 件: `errors.txt` が空になり、終了コードが 0
  - 既存の `errors.txt` があるとき: 上書きされる
