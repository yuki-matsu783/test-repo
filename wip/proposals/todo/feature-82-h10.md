## 目的

README.md の「使い方」の節に、main.sh の呼び出し例と、そのときの出力の例を足す。読んだ人が引数の並びと出力ファイルの形をすぐ掴めるようにする。

## 範囲

- README.md の「使い方」の節（書式と引数の表の後）に「例」の小節を足す。
- 例は 2 つ。(1) 絞り込みで行が残る場合 (2) 一致する行が無く空の出力になる場合。
- 各例は、入力ファイルの中身、実行するコマンド、出力ファイル（`<接頭辞>.txt`）の中身を示す。
- 出力の中身は、実際に main.sh を走らせた結果をそのまま写す（手で作らない）。確かめに使う入力ファイルは scratchpad に置き、リポジトリには入れない。
- 既存の MR の差分（README 末尾の `<!-- 82 検証用の下書き -->` の印）はそのまま残す。

## 対象外

- main.sh のコード（使い方の表示文・処理）は変えない。
- README の他の節（仕様・完成の確認）は変えない。
- 他のファイル（index.html、.ccnavi/ など）は触らない。

## 完了の確かめ方

- README の例のコマンドを、リポジトリの直下で実際に走らせ、出力が README に書いた中身と一致する。
- 例の 2 つとも、`sh main.sh` の引数の順（入力ファイル、絞り込みパターン、出力の接頭辞）に合っている。
- `git diff` の変更が README.md の 1 ファイルだけ。main.sh に差分が無い。
- MR の差分の履歴は書き換えない（新しいコミットを積む）。

## 計画の理由

作業は README の 1 ファイルの追記だけで、順番に進める作業が 1 つあるだけ。設計判断も並行作業も要らないので quick-work で足りる。
