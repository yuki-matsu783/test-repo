## 目的

README の仕様どおりに `main.sh` の `main` 関数を完成させ、`sh main.sh <入力ファイル> <絞り込みパターン> <出力の接頭辞>` で
絞り込み・整形・書き出しができる状態にする。

現状の確認: `main.sh` は `main` 関数まで書かれており、TODO の印は残っていない（既存のコミット `766aeed` が
「README の仕様どおりに実装する (#42)」として入っている）。手元で仕様の 4 点（引数不足、入力なし、一致なし、通常の整形）を
試したところ、いずれも README の期待どおりに動いた。したがって、この作業の中身は「仕様との照合と、ずれがあれば直す」になる。

## 範囲

- `main.sh` のみ。仕様との差が見つかったときに直すのも、この 1 ファイルの中だけ。
- 整形の中身（行頭の空白を除く、番号を振る）は、既存の実装のまま残す。README は「自由に決めてよい」としている。

## 対象外

- `README.md`、`index.html`、`.vscode/`、`.ccnavi/` 以下は変えない。
- テストの追加（受入テストのフェーズは使わない。確かめ方は下の「完了の確かめ方」に書く）。
- 整形ルールの変更、オプションの追加、入出力形式の変更。

## 完了の確かめ方

子のワークツリーで、次を手で確かめて結果を子の完了の報告に書く。

1. 引数が 3 つに満たないとき、使い方を標準エラーに出して終了コード 1 で終わる。
2. 入力ファイルが無いとき、エラーを標準エラーに出して終了コード 1 で終わる。
3. パターンに一致する行が無いとき、`<接頭辞>.txt` が空で作られ、終了コード 0 で終わる。
4. 一致する行が `N. 内容` の形で、行頭の空白が除かれて書かれる。空パターンは全行に一致する。
5. `sh -n main.sh` が通る。

## 計画の理由

作業が 1 ファイルに閉じ、設計や並行作業が要らないので、`quick-work` の 1 ステップ（親 1 子 1）で回す。
