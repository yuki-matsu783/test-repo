# main.sh の --verbose 設計

調査の結果: wip/research/summary.md。
この設計書は、受入テストの作成（後のフェーズ）が、この文書だけを見て書けるように、振る舞いを例で書く。

## 0. 調査との照合

- main.sh（49 行）と README.md を読み直し、調査の結果と照合した。行番号（引数の検査 22〜26 行、入力の検査 32〜35 行、awk 39〜46 行）、使い方の文面（23〜24 行）、終了コード（引数不足と入力無しは 1、一致なしは 0）、出力先（`<接頭辞>.txt`、標準出力は空）は、調査の結果と食い違わない。
- 食い違いは 1 点だけ: README は「`main` 関数の TODO の箇所を完成させる」と書くが、main.sh に TODO は無く処理は実装済み。これは README の記述の問題で、この設計の振る舞いには影響しない（README は対象外）。
- 調査の報告のうち、メインが再実行していない項目（例: 出力先ディレクトリが無いときの終了コード 2）は、この設計では変えない前提だけに使い、正しさを前提にしない。

## 1. 引数の受け方

ルール:

- `--verbose` は、先頭の引数（`$1`）に限って、オプションとして受ける。先頭が `--verbose` のときだけ外し、残りを位置引数として数える。
- 先頭に 1 個だけ受ける。2 個目以降の `--verbose` は位置引数として扱う（入力ファイル・パターン・接頭辞のどれかになる）。
- `--verbose=1` や `-v` などの別の形は認めず、位置引数として扱う。

表（`sh main.sh ...` の後ろの部分。`access.log` は存在するファイル、`nofile` は存在しないファイルとする）:

| 呼び出し | --verbose | 位置引数の解釈 | 振る舞い（終了コード） |
|---|---|---|---|
| `access.log ERROR errors` | なし | 入力 `access.log`、パターン `ERROR`、接頭辞 `errors` | 今と同じ（経過は出ない、0） |
| `--verbose access.log ERROR errors` | あり | 同上 | 経過を標準エラーに出す（0） |
| `--verbose` | あり | 0 個 | 使い方を標準エラーに出す（1） |
| `--verbose access.log ERROR` | あり | 2 個 | 使い方を標準エラーに出す（1） |
| `--verbose nofile ERROR errors` | あり | 入力 `nofile` | `エラー: 入力ファイルが見つかりません: nofile`（1） |
| `--verbose --verbose access.log ERROR errors` | あり | 入力 `--verbose`（存在しない） | `エラー: 入力ファイルが見つかりません: --verbose`（1） |
| `--verbose access.log ERROR errors extra` | あり | 4 個目 `extra` は無視（今と同じ） | 経過を出す（0） |
| `access.log --verbose errors` | なし | パターン `--verbose` | 今と同じ（パターンとして扱う） |
| `access.log ERROR errors --verbose` | なし | 4 個目 `--verbose` は無視（今と同じ） | 今と同じ（経過は出ない） |
| `--verbose=1 access.log ERROR errors` | なし | 入力 `--verbose=1`（存在しない） | `エラー: 入力ファイルが見つかりません: --verbose=1`（1） |

引数の個数の検査（今の `$# -lt 3`）は、先頭の `--verbose` を外した後の個数で行う。

## 2. 経過の出力

### 2.1 出す先と順序

- 出す先は標準エラー（`>&2`）。標準出力には何も出さない。
- 出すのは `--verbose` があるときだけ。
- 入力ファイルの検査（32〜35 行）を通ってから、最初の 3 行を出す（awk の前）。
- 一致した行数は、awk が出力ファイルを書き終えた後に 1 行出す。
- 入力の検査で止まる場合（引数不足・入力無し）は、`--verbose` の有無によらず標準エラーの内容は同じ（経過の行は出ない）。

### 2.2 項目と書式

| 順 | タイミング | 書式 |
|---|---|---|
| 1 | 入力の検査の後 | `経過: 入力ファイル: <入力ファイル>` |
| 2 | 1 の次 | `経過: 絞り込みパターン: <パターン>`。パターンが空文字のときは `経過: 絞り込みパターン: （空: 全行）` |
| 3 | 2 の次 | `経過: 出力先: <出力の接頭辞>.txt` |
| 4 | awk の後 | `経過: 一致した行数: <n>` |

- 入力ファイル・パターン・出力先は、引数の文字列をそのまま出す（引用符で囲まない、エスケープしない）。
- 一致した行数 `<n>` は、awk が書いた出力ファイルの行数。出力ファイルの各行は一致した行 1 つに対応するので、一致が無いときは 0。数えるのは `awk 'END { print NR }' "$output"`。
- 項目に時刻・所要時間・入力の行数は入れない（決めなかった点を参照）。

### 2.3 例

入力ファイル `access.log` の中身（先頭が 2 空白の行あり。行末は改行で終わる）:

```
  ERROR disk full
INFO started
  ERROR net down
WARN slow
```

例 A: `sh main.sh --verbose access.log ERROR errors`

- 標準エラー:
  ```
  経過: 入力ファイル: access.log
  経過: 絞り込みパターン: ERROR
  経過: 出力先: errors.txt
  経過: 一致した行数: 2
  ```
- 標準出力: なし。終了コード 0。
- `errors.txt` の中身（行頭の空白は除かれ、番号が振られる）:
  ```
  1. ERROR disk full
  2. ERROR net down
  ```

例 B: `sh main.sh access.log ERROR errors`（`--verbose` なし）

- 標準エラー: なし。標準出力: なし。終了コード 0。
- `errors.txt` は例 A と同じ中身。

例 C: `sh main.sh --verbose access.log NOPE none`（一致が無い）

- 標準エラー:
  ```
  経過: 入力ファイル: access.log
  経過: 絞り込みパターン: NOPE
  経過: 出力先: none.txt
  経過: 一致した行数: 0
  ```
- 終了コード 0。`none.txt` は 0 バイトで作られる。

例 D: `sh main.sh --verbose access.log "" all`（空パターン）

- 標準エラー:
  ```
  経過: 入力ファイル: access.log
  経過: 絞り込みパターン: （空: 全行）
  経過: 出力先: all.txt
  経過: 一致した行数: 4
  ```
- 終了コード 0。`all.txt` は 4 行（`1. ERROR disk full` から `4. WARN slow`）。

例 E: `sh main.sh --verbose nofile ERROR errors`（入力無し）

- 標準エラー: `エラー: 入力ファイルが見つかりません: nofile` の 1 行だけ（`--verbose` なしと同じ）。
- 終了コード 1。`errors.txt` は作られない。

例 F: `sh main.sh --verbose`（引数不足）

- 標準エラー: 使い方 2 行（今の 23〜24 行の文面そのまま）。
- 終了コード 1。

例 G: `sh main.sh --verbose access.log ERROR nodir/x`（出力先のディレクトリが無い）

- 標準エラー: 経過 3 行（入力・パターン・出力先）の後に、sh が出す書き込みエラー。一致した行数の行は出ない。
- 終了コード: `--verbose` なしと同じ（調査の報告では 2。この設計では変えない）。

## 3. 既定の出力と終了コードが変わらないことの根拠

`--verbose` を付けないときに変わるのは、先頭の `--verbose` の判定（`$1` が `--verbose` でない限り何もしない）だけ。

- 経過の出力は `if [ "$verbose" -eq 1 ]` の中だけ。`verbose` が 0 のときは、今の処理と同じ行だけが動く。
- awk のプログラム（39〜46 行）と、出力のリダイレクト（46 行）は変えない。標準出力は今と同じく空。
- 使い方の文面（23〜24 行）は変えない。引数不足・入力無しのエラー文面と終了コード 1 は今と同じ（調査の結果 §1・§2）。
- 一致なし（0 バイトの出力、終了コード 0）、空パターン（全行）、空入力（終了コード 0、空の出力）は、調査の結果 §3 のとおり。この設計で変わらない。
- 出力の上書き（既存の `.txt` を書き換える）は、調査の結果 §4 のとおり。変わらない。
- 4 個目以降の引数の無視も、調査の結果 §1 のとおり。変わらない。

先頭の `--verbose` を外す処理で、今と違う結果になるのは次の 1 つだけ:

- 呼び出しの先頭が `--verbose` で、かつそれが既定の呼び出しとして使われていた場合。たとえば、カレントに `--verbose` という名前のファイルがあり `sh main.sh --verbose ERROR errors` と打っていたとき、今は、そのファイルを読む。この設計では、`--verbose` としてオプションに解釈する。
  - これは「`--verbose` を付けた呼び出し」に当たるので、既定の出力の変更ではない、と扱う。
  - 回避: ファイル名を `./--verbose` と書けば、今と同じく位置引数として読める。

## 4. 使い方の文面

- 使い方の文面（23〜24 行）には `--verbose` を載せない。
- 理由: 引数不足のときの標準エラーは既定の出力の一部。文面を変えると、`--verbose` なしの出力が変わる。`--help` は対象外。
- 冒頭コメント（6 行目と 8〜16 行）に `--verbose` を 1 行足すのは、実装の段で構わない（実行の出力に影響しない）。

## 5. 決めなかったことと理由

- `-v` の短い形: 追加しない。チケットは `--verbose` だけを対象にしている。必要なら後で決める。
- `--` でオプションを終える形、`--verbose` の複数回指定: 認めない（先頭 1 個のみ）。`--` の導入は引数の形を広げるので、今は決めない。
- 使い方の文面に `--verbose` を載せるか: 載せない（§4）。`--help` を足すかどうかも、対象外のまま。
- 経過の項目を増やすこと（時刻、所要時間、入力の行数など）: 決めない。チケットの 4 項目（入力・パターン・一致行数・出力先）に限る。
- パターンに改行などを含む場合の表示: 決めない。そのまま出す。改行を含むパターンは、今の awk の処理でも扱いが分かれていないので、受入テストの対象外とする。
- 色・装飾・言語切替: 決めない。日本語の固定。
- 一致行数の数え方を `wc -l` にするか: `awk 'END { print NR }'` にする。`wc` は環境によって数の前に空白が付くため。
- 出力先のファイルを作る前に経過を出すかどうか: 出す（§2.1、例 G で確認する振る舞い）。
