```markdown
# 実装の完了報告に実出力を貼る

- 報告の前に、変えたファイルの構文を確かめ（シェルなら `sh -n <パス>`）、変えた動作を実際に動かす（例: `sh <パス> --version`）。両方とも、終了コードと一緒に出力を報告へそのまま貼る
- 「確認済み」「動いた」と口頭で書くだけでは報告にしない。利用者は口頭の確認を信用しないため
- 実行の結果が期待と違うときは、直してから打ち直す。貼るのは打ち直した後の出力だけにする
- この規則は、このプロジェクトの実装の作業すべてに適用する（毎回。1 回限りの確認ではない）

なぜ: 口頭の確認だけでは、動いたかどうかを利用者が後から確かめられないため。
```
